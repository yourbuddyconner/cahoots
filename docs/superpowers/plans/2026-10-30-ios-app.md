# The iOS app, first version: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native iOS app on TestFlight in which two phones meet, make a circle with their cameras, and chat through the default relay, with each phone's seat key in the Secure Enclave.

**Architecture:** Chat moves to root epochs everywhere (one scheme), so a card's phone can join later without a second mode. A new crate, `cahoots-phone`, holds the app's state machine over the existing crates and exposes it through UniFFI; Swift supplies three callbacks (the enclave signer, HTTP to the relay, nothing else cryptographic) and renders. An XcodeGen project builds the app against an XCFramework the Rust build produces.

**Tech Stack:** Rust 1.94 (workspace), `uniffi` 0.29 with proc-macros, `cargo build` for `aarch64-apple-ios` and `aarch64-apple-ios-sim`, `xcodebuild -create-xcframework`; Swift 5.10, SwiftUI, iOS 17 floor, CryptoKit `SecureEnclave.P256.Signing`, AVFoundation, URLSession, BackgroundTasks; XcodeGen (`brew install xcodegen`) for the project file; Xcode 15.4 on this Mac.

**Spec:** `docs/superpowers/specs/2026-10-30-ios-app-design.md`

## Global Constraints

- Everything cryptographic is in Rust; Swift holds no key material outside the enclave and signs only through the callback.
- One chat scheme: root epochs (`HMAC(root, "chat" || circle_id || n)` through `cahoots_core::root::chat_key`), rotation as a numbered epoch, no pad spent by chat. Pad epochs are retired; the wire header stays version 2 and 5 bytes of epoch id, encoded as `slice = 0xFF, offset = n`.
- iOS 17 and later; no third-party Swift packages; plain words in all copy, no em dashes or semicolons in prose; "(phone)" marks what a phone claims about itself where the badge would say "(laptop)".
- The phone declares tier 0; its `Describe`-equivalent says "seat key in the Secure Enclave, secret protected by iOS".
- Enclave keys use user-presence access control; protected files are excluded from backup; keys, pad, root, epoch keys and plaintext under complete protection, ciphertext and cursors under protection until first unlock.
- `cargo test --workspace`, `cargo clippy --workspace --all-targets` (only the pre-existing cahoots-vectors warning), `node web/e2e.mjs` (two browsers chat through a local station) and `cargo run -p cahoots-vectors -- --check` pass before each commit that touches them; the Xcode project builds for the simulator in each task that touches it.
- Pairing, the tap and any badge firmware change are NOT in this plan (they follow M4j); the app's screens for a paired card are not built here.

## Review Focus

- A phone that receives a chat message for a root epoch far ahead of any it has seen (an attacker in the circle posting `n = 2^32 - 1`) must not derive and keep unbounded epoch states; Task 1's test `an_epoch_far_ahead_is_refused`.
- A circle exported by the browser app before this change (state version 4, no root) must open, show its messages, and say chat needs a new ceremony rather than crash; Task 1's test `a_version_4_state_opens_without_chat` in the wasm crate.
- A ceremony interrupted by the app going to the background must come back to the same screen or say plainly it was lost, never leave a half-built circle in the store; Task 2's test `a_ceremony_is_not_saved_until_the_words_match`.
- A signature request while the phone is locked (background refresh) must fail cleanly, not deadlock on Face ID; Task 3's enclave wrapper returns an error and the Rust side treats it as "try later"; test `signing_while_locked_fails_cleanly` with a fake signer.
- The relay unreachable for minutes must not lose a typed message or duplicate it when the network returns; Task 2's test `a_message_posted_during_an_outage_is_sent_once`.

- Produces (UniFFI, proc-macro `#[uniffi::export]`, one object):
  ```rust
  #[uniffi::export(callback_interface)] pub trait Signer: Send + Sync {
      fn make_key(&self, label: String) -> Result<Vec<u8>, PhoneError>;       // P-256 compressed public key, 33 bytes
      fn sign(&self, label: String, message: Vec<u8>) -> Result<Vec<u8>, PhoneError>;  // 64-byte r||s
  }
  #[uniffi::export(callback_interface)] pub trait Http: Send + Sync {
      fn get(&self, url: String) -> Result<Vec<u8>, PhoneError>;
      fn post(&self, url: String, body: Vec<u8>) -> Result<Vec<u8>, PhoneError>;
  }
  #[derive(uniffi::Object)] pub struct Phone { .. }
  #[uniffi::export] impl Phone {
      #[uniffi::constructor] pub fn open(dir: String, signer: Box<dyn Signer>, http: Box<dyn Http>) -> Result<Arc<Phone>, PhoneError>;
      pub fn circles(&self) -> Vec<CircleSummary>;                // id hex, name, members, my_seat, has_root, unread, relay
      pub fn start_ceremony(&self, name: String, members: u8, pad_len: u32) -> Result<String /*ceremony id*/, PhoneError>;
      pub fn join_ceremony(&self, params_code: String) -> Result<String, PhoneError>;
      pub fn ceremony_frames(&self, id: String) -> Result<Vec<String>, PhoneError>;   // the codes to show now, as text payloads (the fountain frames of the current round)
      pub fn ceremony_scan(&self, id: String, text: String) -> Result<CeremonyState, PhoneError>;  // feed one decoded code; returns phase, missing seats, words when done
      pub fn ceremony_keep(&self, id: String) -> Result<String /*circle id*/, PhoneError>;     // after the words match; the circle is written only here
      pub fn ceremony_discard(&self, id: String);
      pub fn decode_frame(&self, width: u32, height: u32, gray: Vec<u8>) -> Option<String>;   // QR decode of a camera frame
      pub fn qr_matrix(&self, text: String) -> Result<QrMatrix, PhoneError>;                 // size and bits for Swift to draw
      pub fn send_chat(&self, circle: String, text: String) -> Result<(), PhoneError>;        // encrypts, appends to the outbox, flushes
      pub fn poll(&self, circle: String) -> Result<Vec<ChatMessage>, PhoneError>;             // fetches from the relay after the cursor, decrypts, stores, returns new ones
      pub fn history(&self, circle: String) -> Vec<ChatMessage>;
      pub fn rotate(&self, circle: String) -> Result<(), PhoneError>;
      pub fn hello_words(&self, circle: String, other_seat: u8) -> Result<HelloWords, PhoneError>;  // mine, theirs, number; next_hello(circle, other_seat)
      pub fn set_relay(&self, circle: String, url: String) -> Result<(), PhoneError>;
      pub fn export_history(&self, circle: String) -> Result<String, PhoneError>;             // readable text, nothing secret
      pub fn delete_circle(&self, circle: String) -> Result<(), PhoneError>;
      pub fn describe(&self) -> PhoneInfo;   // key store sentence, app version, this phone's key fingerprint
  }
  ```
  Records live in `dir`: `circles/<id>/circle.cbor` (params, seat, manifest, root, seat public key label), `pad.bin`, `ledger.bin`, `chat.cbor` (session state, cursor, outbox), `messages.log`; `phone.cbor` (the phone's own key label and fingerprint). The store never writes a circle before `ceremony_keep`. The signer label for a circle's seat is `cahoots:seat:<circle id hex>`; the phone's own key is `cahoots:phone`. `send_chat` appends to an outbox before posting and removes an entry only on a `201` with the relay's `seq`, so an outage re-posts the same bytes once (the relay dedupes nothing for chat, so the outbox entry carries its own id and `poll` skips an incoming entry whose bytes equal an outbox entry it posted).
  `scripts/ios-framework.sh`: `cargo build -p cahoots-phone --release --target aarch64-apple-ios --target aarch64-apple-ios-sim`, `cargo run -p cahoots-phone --bin uniffi-bindgen -- generate --library target/aarch64-apple-ios/release/libcahoots_phone.dylib --language swift --out-dir target/ios/bindings`, then `xcodebuild -create-xcframework` with both static libraries and the generated header/modulemap into `target/ios/CahootsCore.xcframework`, and copies `target/ios/bindings/*.swift` beside it.

- Produces:
  ```rust
  // cahoots_core::channel
  pub const CHANNEL_DOMAIN: &[u8] = b"cahoots/ceremony/channel/v1";
  pub struct Channel { pub id: [u8; 16], key: Zeroizing<[u8; 32]> }
  impl Channel {
      pub fn new(rng: &mut impl CryptoRngCore) -> Channel;
      pub fn offer(&self, params: &CircleParams) -> String;             // the code text: "cahoots:ceremony:v1:" + base64url(id || key || params CBOR)
      pub fn from_offer(text: &str) -> Result<(Channel, CircleParams), ChannelError>;
      pub fn seal(&self, seat: u8, round: Round, payload: &[u8], rng: &mut impl CryptoRngCore) -> Vec<u8>;   // ChaCha20-Poly1305, random 12-byte nonce, AAD = id || seat || round
      pub fn open(&self, wire: &[u8]) -> Result<(u8, Round, Vec<u8>), ChannelError>;
  }
  pub enum Round { Commit = 1, Reveal = 2, Attest = 3 }
  ```
  The station treats version 3 like chat: it stores the body under the 16-byte id and serves it in order. A ceremony through the relay is: the host makes a `Channel`, shows `offer(params)` as one static QR, each joiner scans it (the optical handshake), picks a seat, and every member posts its commitment, then its reveal, then its attestation, sealed, under the channel id, and fetches the others' from the same place; the round logic is the existing `Ceremony`. The six words are compared aloud at the end as today. The channel id is unguessable and the key never leaves the code, so the relay holds ciphertext it cannot open and a stranger's post fails to open and is dropped. The animated-code path is unchanged and remains the fallback that needs no network.
