# Chip apps implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Seat keys in the SE051, attestation, SSH and git signing from the seat key, contact cards, many circles per badge, grants as CBOR Web Tokens, all behind one new request family on the custodian protocol, testable without hardware.

**Architecture:** A new `no_std` crate `cahoots-chip` defines `ChipOps` with a software backend (`SoftChip`) and an `se05x` backend for the Pico. `cahoots-core` gains a `SeatSigner` trait so the ceremony signs through either a software key or a chip key. `cahoots-custodian` gains `Request::Chip`/`Response::Chip`. `cahoots-objects` gains cards, attestation verification and grant v2. `cahoots-badge` gains the chip record, the circle list, the chooser and the consent screens. `cahoots-host` gains `agent`, `git-sign`, `roster`, `attest`, `card`. `crates/rp2350` wires the real chip.

**Tech Stack:** Rust 1.94 workspace, `minicbor`, `p256`, `ed25519-dalek`, `hmac`/`sha2`/`hkdf`, `coset` (tests only), `se05x` 0.4.2 (firmware only), `ssh-key` and `ssh-encoding` crates for SSH wire formats on the host, `x509-cert`/`der` for the attestation chain.

**Spec:** `docs/superpowers/specs/2026-10-28-chip-apps-design.md`

## Global Constraints

- Rust edition and toolchain as the workspace (`rust-toolchain.toml`, 1.94); `crates/rp2350` builds outside the workspace with `cargo build --release` in the crate.
- Library crates are `no_std` + `alloc` where the badge uses them (`chip`, `custodian`, `objects`, `core`, `badge`); host-only code lives in `crates/host`.
- Workspace license `MIT OR Apache-2.0`; `se05x` (LGPL-3.0-only) is a dependency of `crates/rp2350` only, behind `ChipOps`.
- No panics on untrusted input; every request parser returns an error, never unwraps.
- Copy rules: plain words, no coined names, every consent screen names A, A+B and B in the footer, every unverified value ends with "(laptop)".
- CBOR: array-encoded enums as in `crates/custodian/src/wire.rs`; existing variant indices never change; decoders re-encode and reject non-canonical input as today.
- Key ids: `0x4C41_0000 | kind << 8 | slot` with `Seat = 1`, `Root = 2`, `Epoch = 3`.
- Root derivation: `HKDF-SHA256(ikm = X-Wing reveal secrets concatenated in seat order, salt = circle_id, info = "cahoots/root/v1")`, 32 bytes.
- Chat key derivation: `HMAC-SHA256(root, "chat" || circle_id || epoch as u64 BE)`.
- Card seal key: `HMAC-SHA256(root, "seal/card" || circle_id)`.
- Commit after every task with a message in the repo's style (plain sentences, what and why).

## Review Focus

- A `SshSign` request whose `data` is not a userauth request or an `SSHSIG` envelope must be refused with `Unparseable`, never signed. Test in Task 6.
- A session binding whose session id differs from the one in `data` must be shown as "host not named", never as the bound host. Test in Task 6.
- Git content whose SHA-512 does not match the `SSHSIG` hash must be refused. Test in Task 6.
- A chip object present in a slot the chip record does not know must be deleted on boot and logged, never reused. Test in Task 8.
- Two circles on one badge must share no derivable value: seat keys, roots and slots differ, and `Identity` lists both with nothing linking them. Test in Task 8.
- A grant v2 whose `cnf` key does not match the grantee named in the chain must fail `verify_chain`. Test in Task 9.
