# cahoots.network

The landing page, docs site and blog. Static files, no bundler. Deployed to GitHub Pages by `.github/workflows/pages.yml` on every push to `main`, which also builds the browser app into `/app`, copies the markdown docs into `/docs/md`, and renders the blog.

## Preview locally

```sh
mkdir -p site/docs/md site/docs/diagrams && cp README.md site/docs/md/readme.md && cp docs/*.md site/docs/md/ && cp docs/diagrams/*.svg site/docs/diagrams/
cp web/README.md site/docs/md/web.md && cp crates/station/README.md site/docs/md/station.md && cp crates/chat/README.md site/docs/md/chat-cli.md
cp crates/host/README.md site/docs/md/host.md && cp crates/ADAPTERS.md site/docs/md/adapters.md
cp crates/rp2350/README.md site/docs/md/rp2350.md && cp hardware/v1/README.md site/docs/md/v1-board.md
python3 scripts/build-blog.py --out site      # needs `pip install markdown`; add --skip-og without Chrome
cd site && python3 -m http.server 8787
```

## Blog

Posts are markdown files in `blog/`, named `YYYY-MM-DD-slug.md`, with front matter for `title`, `date`, `description` and optionally `author`, `role`, `tags` (comma separated), `about`, `audience`, `learn` (a `- ` list, shown in the box above the post), `image` (a 2:1 picture for the top of the post), `slug` and `draft: true`. `scripts/build-blog.py` renders `/blog/`, `/blog/<slug>/` (with an "In this article" list from the h2 headings, a share row and the post's markdown at `/blog/<slug>.md`), an RSS feed at `/blog/feed.xml`, one Open Graph card per post (`assets/og-blog-<slug>.png`, from the same `og/og.css` as the other cards) and, when no `image` is given, a generated 1600x800 hero (`assets/hero-blog-<slug>.png`), all with headless Chrome. The rendered output under `site/blog/` and the generated images are gitignored; `site/blog/blog.css` is the only committed file there.

The landing page is `index.html` with its own `landing.css`. `brand.css` provides shared color, typography, and identity tokens for the landing page, docs, and journal, on top of the existing shell in `style.css`. Its hero is an inline SVG explaining how devices form a circle; it needs no JavaScript or external fonts. The hardware section lazy-loads `badge-loader.js` and `badge-render.js`, displaying `assets/badge-v1.glb`, exported directly from `hardware/v1/v1.kicad_pcb`. It rotates the assembly and separates the actual enclosure and display nodes. The view provides a pause control, honors reduced motion, and falls back to the current `assets/v1-front.png` when WebGL is unavailable. Three.js 0.186.0, the GLTF loader dependencies, and the MIT license are vendored under `vendor/three/` with local imports.

Regenerate the browser model and refresh the fallback image after a PCB change:

```sh
python3 scripts/export-site-badge.py
```

This requires KiCad 10; set `KICAD_CLI` if it is not on PATH or installed at the default macOS location. KiCad exports component geometry, silkscreen, soldermask, pads, and the enclosure. The viewer restores the enclosure transparency specified in the WRL sources, since STEP substitution loses alpha. The exporter reports unavailable footprint models: the current export uses alternate models for SW2/SW3, while SW1/SW4 and U2 lack local models and are omitted. Those are source CAD limitations, not substitute geometry in the viewer.

Legacy illustrations are generated by `site/art/gen.py`. The Open Graph artwork under `site/og/` is maintained separately from the landing page.

## One-time setup

1. GitHub → repository → Settings → Pages → Source: **GitHub Actions**.
2. Settings → Pages → Custom domain: `cahoots.network`, then tick **Enforce HTTPS** once the certificate is issued. `site/CNAME` already carries the name.
3. DNS at the registrar for `cahoots.network`:

   | Type | Name | Value |
   |---|---|---|
   | A | @ | 185.199.108.153 |
   | A | @ | 185.199.109.153 |
   | A | @ | 185.199.110.153 |
   | A | @ | 185.199.111.153 |
   | CNAME | www | yourbuddyconner.github.io |

4. `cahoots.tools`: a forwarding rule at the registrar to `https://cahoots.network` (301), or the same records if it should also serve the site. Only one custom domain can be set on the Pages site.


## Documentation reading path

`site/docs/catalog.js` defines the sidebar and retained direct routes. Public guides live in `docs/overview.md`, `ceremony-guide.md`, `browser.md`, `relay.md`, `hardware.md`, `security.md`, and `status.md`. The Pages workflow already copies these with the other `docs/*.md` files. The overview is a reader guide rather than the repository README.

`ARCHIVED` entries remain accessible at their existing hash routes and through contextual links, but are omitted from the sidebar and sequential reading path. They include detailed build notes, research ideas, and the engineering roadmap. Keep protocol and chat specifications separate from the user guides; describe implementation status explicitly instead of presenting planned behavior as available.
